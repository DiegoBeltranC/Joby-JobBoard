# Idioma (i18n)

Scope: how user-facing text and domain vocabulary are handled in bolsa-trabajo.

## Reality: Spanish, no i18n library

The product is **Spanish-only** (UT Chetumal). There is no `next-intl`, `react-i18next`, or
`formatjs` dependency and no translation files. All UI copy is written as **plain Spanish string
literals** directly in the JSX (`"Publicar vacante"`, `"Tu postulación fue enviada"`), and the
`<html lang="es">`.

## Rules

- Write user-facing text as **Spanish literals**. Do **not** introduce translation keys (`t('...')`)
  or an i18n library unless a task explicitly asks to add multi-language support.
- **Domain vocabulary is Spanish and matches the database/schema** — `correo`, `contraseña`,
  `estudiante`, `empresa`, `vacante`, `postulación`, `perfil`, `carrera`, `habilidades`. Keep new code
  consistent with the existing Spanish naming; don't "translate" identifiers to English (see
  code-standards.md).
- Enum values from Prisma are Spanish/uppercase (`ESTUDIANTE`, `EMPRESA`, `ADMIN`, `PRESENCIAL`,
  `TIEMPO_COMPLETO`, …) — use them as-is.
- Dates/numbers: format for Mexico (`toLocaleDateString("es-MX", …)`), as the existing code does.
